1. What is Playwright and how is it different from Selenium?
Playwright is an end-to-end testing framework developed by Microsoft. It supports Chromium, Firefox, and WebKit browsers with auto-waiting and faster execution. Unlike Selenium, it does not require external drivers and provides built-in tracing, video, and parallel execution support.
2. What are Browser, Context, and Page in Playwright?
  • Browser: Actual browser instance (Chrome/Firefox/WebKit)
  • Context: Isolated session like incognito window
  • Page: A single tab inside a context
3. What is auto-waiting in Playwright?
Playwright automatically waits for elements to be Visible, Stable, and Enabled before performing any actions, reducing the need for manual waits.

while finding the element in the DOM, it will check in the dom is the element is present or not, if present it will automatically waits for element to be visible stable and enables and if needed it will automatically scroll into the view

4. Difference between locator() and page.$()?
  • locator() is Playwright's modern and recommended way of finding elements. It supports auto-waiting, retryability, and always interacts with the latest state of the element.
  • page.$() returns an ElementHandle immediately and does not provide auto-waiting or retryability. It is generally discouraged in favor of locator().
  • locator() supports auto-waiting and is recommended
  • page.$() returns element handle without auto-waiting
5. How do you handle dynamic elements?
Use stable selectors like:
  • getByRole()
  • getByText()
  • data-testid attributes
  • by chaining the locators
  • by finding the parent element first and then the child
    • Example: page.locator('.product-card').locator('button')

Avoid fragile XPath selectors (in playwright it is not recommanded approach)

6. Why use TypeScript with Playwright?

TypeScript is commonly used with Playwright because it provides type safety, better code quality, and improved developer productivity.

Key Benefits of Using TypeScript with Playwright

  1. Type Safety
    • Detects errors during development instead of runtime.
    • Helps prevent common coding mistakes.
  2. IntelliSense & Auto-Completion
    • Provides method suggestions and code completion in IDEs like VS Code.
    • Speeds up development and improves accuracy.
  3. Better Code Maintainability
    • Makes large automation projects easier to manage.
    • Improves readability and collaboration among team members.
  4. Early Error Detection
    • Catches issues at compile time before test execution.
    • Reduces debugging effort.
  5. Improved Refactoring
    • Allows safer renaming and restructuring of code.
    • Helps identify affected files automatically.
  6. Object-Oriented Programming Support
    • Supports classes, interfaces, inheritance, and access modifiers.
    • Useful for implementing the Page Object Model (POM).

Short Interview Answer

"I use TypeScript with Playwright because it provides type safety, IntelliSense support, and compile-time error checking. It helps catch issues early, improves code maintainability, and makes automation frameworks more scalable and reliable, especially in large projects."

11. Can Playwright be used for API testing?
Yes, Playwright supports API testing using its request context. You can send GET, POST, PUT, DELETE requests and validate responses.

12. What is Playwright Trace Viewer?
Trace Viewer is a debugging tool that helps analyze test failures. It shows screenshots, DOM snapshots, network requests, and actions step-by-step. It is very useful for identifying flaky tests and root causes of failures.
13. How do you run tests in parallel in Playwright?
Playwright runs tests in parallel by default using workers. You can also configure it in the config file. 
workers: 4
This improves execution speed significantly.
14. How do you handle flaky tests?
To handle flaky tests:
  • Use stable locators like data-testid
  • Avoid hard waits (setTimeout)
  • Use Playwright auto-waiting features
  • Use trace viewer for debugging
  • Avoid dependency between tests
15. How do you mock API responses in Playwright?
You can intercept network requests using page.route(). 
await page.route('**/api/users', route =>
  route.fulfill({
    status: 200,
    body: JSON.stringify([{ name: 'John' }])
  })
);
16. What are fixtures in Playwright?
Fixtures are used to set up and tear down test environments. They help share common setup logic like browser, page, or login state across tests.
17. How do you capture screenshots and videos?
You can configure this in Playwright config file. 
use: {
  screenshot: 'only-on-failure',
  video: 'retain-on-failure'
}
This helps in debugging failed tests.
18. What is test isolation in Playwright?
Test isolation means each test runs independently in a separate browser context. This prevents shared state like cookies or sessions from affecting other tests.
19. How do you debug tests in Playwright?
You can debug using:
  • Playwright Inspector
  • Trace Viewer
  • Headed mode execution
  • Console logs and screenshots

Data Types in TypeScript

TypeScript has several built-in data types that can be used to define the type of a variable. Some of the commonly used data types in TypeScript include:

Types in TypeScript

TypeScript types define what kind of data a variable can store. They help detect errors during development.

1. Primitive Types

Type Description Example
string Text values "Hello"
number Numbers (integer or decimal) 10, 5.5
boolean True or false true, false
null Empty value null
undefined Variable declared but not assigned undefined
bigint Very large numbers 123n
symbol Unique identifier Symbol()

Example

                  let name: string = "Rahul";
                  let age: number = 25;
                  let isActive: boolean = true;

2. Array Type

Used to store multiple values of the same type.

                  let numbers: number[] = [1,2,3,4];
                  
                  let names: string[] = ["Ram","Shyam","Sita"];

Alternative syntax:

                  let numbers: Array = [1,2,3];

Advanced array

Array can also hold multiple types using union types.

                  let user: (string | number)[] = ["Hello", 10, "World", 20];
                  user = ["John", 25, "Doe", 30];
                  user =[10, 20, 30, 40];
                  user = ["Alice", "Bob", "Charlie"];

3. Tuple

Tuple allows fixed number of elements with specific types.

                  let user: [string, number];
                  
                  user = ["John", 25];

4. Enum

Enum defines a set of named constants.

                  enum Status {
                    Pending,
                    Approved,
                    Rejected
                  }
                  
                  let orderStatus: Status = Status.Approved;
          
                  enum Role {
                    Admin,
                    Editor,
                    Viewer,
                  }
          
                  let userRole: Role = Role.Admin;

5. Any

Allows any type of value.

                  let data: any = 10;
                  
                  data = "Hello";
                  data = true;

6. Unknown

Safer alternative to any.

            let value: unknown = "Hello";

7. Void

Used when a function does not return anything.

            function logMessage(): void {
            console.log("Hello");
           }

8. Object Type

            let user: {name: string, age: number} = {
            name: "Ravi",
            age: 30
            };

9. Union Type

Allows multiple possible types.

we can add more than 2 types n type can be added

          let id: number | string;
                  
          id = 10;
          id = "ABC123";

10. Literal Types

Restricts variable to specific values.

            let direction: "left" | "right" | "up" | "down";
                  
            direction = "left";

Type alias

Type aliases allow you to create a new custom type we can call it, if we can use that as custom type

                  type userDetail = {
                    name: string;
                    age: number;
                  };

31. What is JSON Schema Validation?

JSON Schema validation is the process of checking whether a JSON document conforms to a predefined schema (a set of rules that describes the expected structure, data types, and constraints).

            Example Json
            
            {
            "name": "Alice",
            "age": 30,
            "email": "alice@example.com"
            }
            
            Corresponding JSON Schema
            {
            "type": "object",
            "properties": {
            "name": {
            "type": "string"
            },
            "age": {
            "type": "integer",
            "minimum": 0
            },
            "email": {
            "type": "string",
            "format": "email"
            }
            },
            "required": ["name", "age"]
            }

What JSON Schema Can Validate

  • Data types (string, number, boolean, array, object)
  • Required fields
  • String length
  • Numeric ranges
  • Array size
  • Allowed values (enum)
  • Email, URI, date formats
  • Nested objects and arrays
32.What is REST APIs

REST API (Representational State Transfer Application Programming Interface) is a set of rules that allows two applications to communicate over HTTP. It enables a client (such as a web application, mobile app, or automation script) to send requests to a server and receive responses.

REST API Methods

HTTP Method Purpose Example
GET Retrieve data Get user details
POST Create new data Create a new user
PUT Update entire resource Update all user details
PATCH Update part of a resource Update only the email
DELETE Remove data Delete a user

HTTP Status Codes

Status Code Meaning
200 OK
201 Created
204 No Content
400 Bad Request
401 Unauthorized
403 Forbidden
404 Not Found
405 Method Not Allowed
409 Conflict
500 Internal Server Error
503 Service Unavailable

Interview Definition (30-second Answer)

REST API stands for Representational State Transfer Application Programming Interface. It is an architectural style that allows a client and server to communicate over HTTP. REST APIs use standard HTTP methods such as GET, POST, PUT, PATCH, and DELETE to perform CRUD operations. They are stateless, meaning each request contains all the information needed to process it, and they commonly exchange data in JSON format.

How You Test REST APIs (QA Interview Answer)

As a QA Engineer, I typically verify the following aspects of a REST API:

  • API Endpoint (URL): Verify that the request is sent to the correct endpoint.
  • HTTP Method: Ensure the correct method is used (GET, POST, PUT, PATCH, DELETE).
  • Request Headers: Validate headers such as Content-Type, Authorization, Accept, and custom headers.
  • Request Payload (JSON): Verify the request body contains valid JSON with the required fields and correct data types.
  • Response Body: Validate that the response data is accurate, complete, and matches the expected values.
  • HTTP Status Code: Check that the API returns the correct status code (200, 201, 400, 401, 404, 500, etc.).
  • Response Time: Ensure the API responds within the acceptable performance threshold.
  • JSON Schema Validation: Verify that the response follows the expected JSON schema, including required fields and data types.
  • Authentication: Validate authentication mechanisms such as Bearer Token, OAuth, API Key, or Basic Authentication.
  • Error Handling: Test invalid inputs, missing mandatory fields, invalid authentication, and unauthorized access to ensure proper error responses are returned.
